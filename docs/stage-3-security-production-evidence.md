## Confirmed findings and residual risks

- **Documentation drift (confirmed):** the prior deployment guide described Netlify as the active frontend and its origin as the CORS target. The old XLSX review described `xlsx@0.18.5` as the current direct dependency. The current tree instead uses ExcelJS and has no installed `xlsx` package.
- **Dependency advisory (confirmed package presence, no inspected vulnerable call):** `uuid@8.3.2` is within the advisory's affected package range. The specific unsafe buffer behavior is associated with `v3`/`v5`/`v6`; inspected ExcelJS code uses `v4` without a caller-supplied buffer. This narrows observed reachability; it does not clear the dependency audit or eliminate future/other call paths.
- **Hosted frontend response headers (unverified):** backend source sets security headers, but Vercel serves static frontend files separately. No repository Vercel configuration was found, and neither a Vercel preview nor legacy Netlify preview/headers prove production Vercel headers. This is an evidence gap, not a confirmed missing-header defect.
- **Backup limitation:** application backups contain catalog snapshots, not full database backups. The disposable PostgreSQL dump/restore rehearsal does not establish Supabase retention or PITR.

No dependencies were installed, upgraded, overridden, or removed. No production data, dashboard settings, migrations, or deployments were changed.
